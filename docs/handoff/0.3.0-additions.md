# Release 0.3.0 additions and continuation handoff

This note closes the implemented and measured release scope and separates it from explicitly
deferred follow-up work. It contains no subscription, support-case, contact, public-IP, credential,
or local-path identifiers.

## Implemented and verified locally

- Full-data DuckDB/Parquet pipeline with frozen source verification, live-feature parity,
  whole-account temporal folds, calibration-derived thresholds, resumable checkpoints, and
  hash-bound publication contracts.
- vLLM BF16/AWQ harness with deterministic release cases, warm-up/development/full profiles,
  checkpointing, NVIDIA telemetry, quality/cost gates, RunPod operator lifecycle, and honest
  mechanical headlines.
- Durable investigation workers using PostgreSQL leases, heartbeats, fencing, reaping, bounded
  retry, replayable events, and explicit pending/running/retrying/failed/drafting-blocked UI states.
- Portable Kubernetes manifests, HPA, kind harness, AKS overlay/Terraform/inert workflow, and
  measured kind evidence: API replicas 1 → 5 → 1 with 100/100 durable runs after worker deletion.
- Research UI for inference/autoscaling/training evidence. Alert review shows risk/SHAP evidence
  and the backend-projected model input.
- Scalar at `/scalar`, OpenAPI JSON/YAML, standalone generated API HTML, nine indexed release ADRs,
  runbooks, claim register, interview guide, and deterministic README evidence regions.

## Measured release evidence

- The Azure batch run processed all 68,228,066 frozen IBM source rows and published three temporal
  candidate evaluations. The temporary resource group was destroyed and clean teardown verified.
- RunPod run `vllm-bench-f810b57a7b8ae05a` completed 6,000 measured requests on an RTX 4090. AWQ
  reduced parsed model-weight memory by 63.5% and improved throughput by 60.8% at concurrency 32.
- AWQ did not meet the reference-validity acceptance threshold. The repository therefore claims
  measured efficiency only and does not claim quality parity or unconditional runtime promotion.
- The 100-case application pass completed through API, durable worker, and vLLM. The temporary Pod
  and encrypted volume were deleted; provider cleanup returned zero matching resources.
- Provider billing settlement may replace conservative projected costs later; it does not require
  compute to be recreated and does not block the measured release evidence.

## Deferred to a later release — do not implement as part of 0.3.0

1. Add a deterministic `SARQualityGate` over ChromaDB-retrieved source spans.
2. Add an AWQ-first cascade with BF16 or GPT-5 mini regeneration after gate failure.
3. Stream per-draft model, validation, rejection, and escalation trace events over SSE.
4. Surface the model-selection trace in the frontend.
5. Publish a dedicated AWQ evaluation narrative citing the FrugalGPT/model-cascade pattern.
6. Ground the future validator explicitly in FinCEN SAR narrative field requirements.
7. Apply the already validated AKS/Terraform deployment and capture AKS-specific evidence.

## Release-claim boundary

- Demonstrated now: full-data training, RunPod BF16/AWQ efficiency evidence, the vLLM application
  path, and local kind HPA/durability evidence.
- Tested/validate-only now: AKS Terraform, manifests, policy, and deployment workflow.
- Not claimed: AWQ quality parity, unconditional AWQ promotion, or a live AKS deployment.
- Azure Container Apps remains the application deployment target; AKS is a demonstration runtime;
  RunPod is a temporary benchmark host only.
