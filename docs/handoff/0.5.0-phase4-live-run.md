## Why the live run failed — nine defects

Every one sits where our code meets something we do not control. None were caught by the test
suite, because the suite verifies our behaviour against fakes we wrote ourselves.

| # | Defect | Where | Status |
|---|---|---|---|
| 1 | RunPod rejects `volumeEncrypted` on pod create | `scripts/lib/runpod_gpu/models.py` | **Fixed** `0c43b87` |
| 2 | `publicIp: ""` before placement crashed create-response parsing, orphaning a billing Pod | `scripts/lib/runpod_gpu/api.py` | **Fixed** `0bbce7b` |
| 3 | RunPod no longer reports volume encryption at all | `scripts/lib/runpod_gpu/session.py` | **Relaxed + recorded** `665da0a`, owner-approved |
| 4 | MooseFS `/workspace` fails `uv sync` with `Stale file handle (os error 116)` | pod filesystem | Worked around per-pod (`~/.config/uv/uv.toml` `link-mode = "copy"`) — **needs a repo fix** |
| 5 | vLLM token left mode `666`: `cat >` keeps an existing file's mode, and MooseFS **ignores `chmod` entirely** | `scripts/lib/runpod_gpu/transfer.py` | Worked around (token copied to container disk) — **needs a repo fix** |
| 6 | `vllm serve --model X` rejected by vLLM 0.10.2, which wants the model positionally | `scripts/lib/vllm_bench/server.py::_server_arguments` | **Not fixed** — blocks `serve` |
| 7 | Sync never uploads the case manifest sidecar the run path requires | `scripts/lib/runpod_gpu/transfer.py::sync_session` | **Not fixed** — worked around by scp |
| 8 | Case path is profile-derived, so a smoke run demands `cases-…-smoke.json` | `scripts/benchmark_vllm.py::_paths` | **Not fixed** — worked around by symlink |
| 9 | `_run_scenario` shells out to `git` for provenance; a Pod holds a `git archive` extraction, not a repository | `scripts/benchmark_vllm.py::_run_scenario` | **Not fixed** — this is what stopped the run |

Defect 9 is the stop condition. Fixing it means a repo change, which re-binds both Pods (see
"Hard constraints") and forces a full rebuild. The only alternative was `git init` on the Pod to
satisfy the check, which would write a fabricated commit hash into published provenance. Do not do
that.

## Fix these before spending again

Ordered by what unblocks the run.

1. **Accept an injected commit in `_run_scenario`** rather than resolving it locally. The commit is
   already known: it is on the RunPod session (`RunpodSession.git_commit`) and passed to the Pod at
   sync time. Add a `--git-commit` argument or read it from the environment the sync sets, and keep
   `git_commit()` for the local/laptop path. Test it with the repository absent.
2. **Model positional in `_server_arguments`** — emit `vllm serve <model>`, not `--model <model>`.
   The docker entrypoint accepts both; the process runtime does not. Add a test that runs the real
   vLLM CLI's argument parser, not one that asserts the flags we chose to emit.
3. **Upload the manifest sidecar in `sync_session`** next to the corpus.
4. **Write the vLLM token to container disk** (`/root/.fraudlens/`), not `/workspace`, and `chmod`
   explicitly instead of relying on `umask`. The network volume is unencrypted and ignores modes,
   so it is not a place for secrets.
5. **Set `UV_LINK_MODE=copy`** in the remote sync command, or ship a `uv.toml` with the synced
   source.
6. **Migrate the RunPod operator to REST v2.** Defects 1–3 are all v1 drift. The v2 shape nests
   settings differently — `gpu.{id,count}`, `mounts.persistent.{size,path}` — and drops
   `interruptible`, `locked`, `computeType`, `gpuTypePriority`, `minDownloadMbps`. The
   `runpod:migrate` skill inventories and rewrites. Until this lands, expect the next drift mid-run.

### The one addition that would have caught all nine

A **throwaway smoke Pod** (~$0.07, five minutes) with a 125M-parameter model, exercising
create → sync → serve → one completion → teardown, run before any full session. Add it as a
`make` target and put it in the `benchmark-vllm` skill ahead of the existing smoke step, which
currently sits *after* provisioning and therefore assumes the part that broke.

A second cheap guard: a **read-only contract check at plan time** that GETs the live pods endpoint
and validates the response against `RunpodPod`. Free, and it catches provider drift before a Pod
exists.

## Hard constraints — do not work around these

- **Golden Rule 1.** No commit or push without explicit human permission. The owner granted
  per-run operational commits for the 2026-09-17 session only; that grant does not carry forward.
- **Golden Rule 7.** No billable or mutating cloud action without explicit permission. That
  includes `runpod-gpu-{up,down,start,stop,sync}`, all of which are ask-gated in
  `.claude/settings.json`.
- **A Pod is bound to the commit its session records.** `sync_session` refuses when local `HEAD`
  differs. This is deliberate: it stops two endpoints running different source, which would void
  the comparison. **Consequence: never commit between creating a Pod and syncing it.** Doing so
  costs a full teardown and rebuild — it happened once in this session.
- **Provenance must never be fabricated.** If a value cannot be obtained honestly, fail and record
  the absence, as the volume-encryption exception does.
- **The v1 report is immutable evidence** (AD-1.3). `config/vllm-bench.yaml`'s `protocol_lineage`
  keeps it hash-bound under protocol v2; do not remove that entry.

## Resuming the live run

Prerequisites: defects 1–5 fixed and committed, `make ci` green, clean worktree, owner approval for
the spend, and an open ledger row **before** the first Pod.

```bash
# 1. Free gates
make vllm-bench-test && make vllm-bench-validate
make vllm-bench-cascade-pilot                       # admission projection, zero spend

# 2. Regenerate the corpus under protocol v2 (~12 min, free, needs .local/fulldata artifacts)
make vllm-bench-cases PROFILE=full SOURCE=ibm-final-test

# 3. Read-only capacity + budget admission, per role
infisical run --env=prod --path=/ml -- make runpod-gpu-plan RUN=<run-id> ROLE=awq

# 4. Open the ledger row, commit it, THEN create Pods (never commit after this point)
infisical run --env=prod --path=/ml -- make runpod-gpu-up RUN=<run-id> ROLE=awq  CONFIRM=yes
infisical run --env=prod --path=/ml -- make runpod-gpu-up RUN=<run-id> ROLE=bf16 CONFIRM=yes
infisical run --env=prod --path=/ml -- make runpod-gpu-sync RUN=<run-id> ROLE=awq  CONFIRM=yes \
  VLLM_CASES=.local/vllm-bench/cases-ibm-final-test-full.json
# …same for bf16

# 5. Serve both, smoke at 8 cases, then c32 × 1000
# 6. Export, reconcile ledger, teardown, verify-clean for BOTH roles
```

Secrets come from Infisical `prod`: `RUNPOD_API_KEY` and `VLLM_API_KEY` at `/ml`,
`OPENROUTER_API_KEY` at `/llm`. The operator SSH identity is `~/.ssh/fraudlens{,.pub}` via
`RUNPOD_SSH_{PRIVATE,PUBLIC}_KEY_PATH`.

### Two-endpoint topology — decide and record this

The plan says both endpoints must be "simultaneously reachable" but never says *from where*, and
the answer changes the measured escalation latency. Each vLLM binds loopback and only `22/tcp` is
exposed. In this session the client ran **on the AWQ Pod**, reaching BF16 through an SSH tunnel
over RunPod's network, using an ephemeral key generated on container disk. Running the client
locally instead would add operator-network latency to every escalated case — the exact figure the
release reports. Whatever is chosen, state it in the report's methodology.

## What the evidence currently supports

The cascade claims rest on the **replay projection over 1,000 persisted cases**, which is committed,
reproducible, and cross-checked by `tests/quality/test_citation_quality.py` and
`tests/quality/test_sar_cascade_quality.py` against the corpus provenance. That is honest evidence
and should be described as a projection.

Not yet evidenced, and requiring the live run: `reference_validity == 1.0` under constrained
decoding (the criterion the v1 run **failed** at 0.839), cascade pass rate ≥ BF16-alone and ≥ 0.99,
the AWQ weight-memory floor re-verified, and any claim that prompt v2's gate rules hold against a
real model — the replay judges prompt-v1 output under the reduced `sar_quality.replay_gate` policy,
so the production gate has never faced live generation.
